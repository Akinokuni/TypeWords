# 02 · 服务端存储层

## 改动目标

把当前存于浏览器 IndexedDB 的**核心数据**迁移到服务端，用 **SQLite** 持久化，前端通过后端 API 读写，实现跨设备一致与 Agent 可访问。练习会话缓存采用「本地为主 + 服务器双备份」：正常运行读写本地，离开/静止时上传服务器，换浏览器自动恢复。

## 现状

### 数据落点（客户端 IndexedDB，经 `idb-keyval`）

| 存储 key | 版本 | 内容 | 定义位置 |
|----------|------|------|----------|
| `typing-word-dict` | 4 | 词典/书籍数据（`BaseState`：word.bookList、article.bookList、fsrsData、noteData、simpleWords 等） | `app/core/config/env.ts` |
| `typing-word-setting` | 23 | 设置（`SettingState`） | 同上 |
| `PracticeSaveWord` | 2 | 单词练习会话缓存（**本地 + 服务器双备份**） | `app/core/utils/cache.ts` |
| `PracticeSaveArticle` | 1 | 文章练习会话缓存（**本地 + 服务器双备份**） | 同上 |
| `PracticeSaveSentence` | 1 | 例句练习会话缓存（**本地 + 服务器双备份**） | `app/composables/practice-sentences/practice-sentence-cache.ts` |
| `typing-word-export` | 5 | 导出数据 | `app/core/config/env.ts` |
| `typing-word-files` | - | 本地文件 | 同上 |
| `type-words-app-version` | 4 | 应用版本 | 同上 |
| `type-words-backup-*` | - | 备份 | 同上 |

### 现有同步（Supabase，可选）

- 表 `typewords_data`：`type` / `data` / `updated_at` / `data_version`。
- 同步类型：`dict`、`setting`、`practice_word`、`practice_article`（`app/core/types/enum.ts` 的 `SyncDataType`）。
- 冲突判定：按 `updated_at` + `data_version`（`shouldFetchRemote`）。
- 配置入口：localStorage `supabase_config`（`app/core/utils/supabase.ts`）。

### 练习会话缓存双备份（本地 + 服务器）

- 三个练习会话缓存（`PracticeSaveWord` / `PracticeSaveArticle` / `PracticeSaveSentence`）**正常运行仍读写浏览器本地 IndexedDB**（快、零请求）。
- **上传时机**：离开页面（`visibilitychange` hidden、`pagehide`）或静止（30 秒无键盘/鼠标/触摸活动）时，把本地缓存上传到服务器作备份；`pagehide` 走 `keepalive` 请求尽力送达。
- **恢复时机**：本地缓存完全不存在（换浏览器/清缓存）时，练习页 `load()` 自动从服务器拉回并回写本地。
- 服务器侧复用 SQLite `store` 表，新增 key：`practice_word` / `practice_article` / `practice_sentence`，经 `/api/data/:key` 读写（白名单见 `server/utils/storeKeys.ts`）。
- 客户端实现：`app/core/composables/usePracticeServerBackup.ts`（`restoreIfAbsent` / `flushToServer` / `start`/`stop`），由 `useInit.ts` 在初始化后启动、卸载/重初始化时清理；三个持久化层（`usePracticePersistence.ts` / `usePracticeSentencePersistence.ts`）的 `load()` 增加服务器兜底恢复。

### 读写入口

- 初始化/持久化：`app/core/composables/useInit.ts`（`store.init()`、`$subscribe` 防抖保存）
- 保存/同步调度：`app/core/composables/useDataSyncPersistence.ts`（`saveDictState` / `saveLocalAndSync` / `syncData`）
- 练习缓存：`app/core/utils/cache.ts` + `app/core/composables/usePracticeServerBackup.ts`（本地为主，服务器双备份）

## 方案（建议）

1. **存储引擎**：**SQLite（已决策）**，使用 `better-sqlite3` 或 Node 内置 `node:sqlite`。数据文件放在服务端数据目录（容器内 `/app/data/typewords.db` → 宿主机 `./data/`）。
2. **数据模型映射**：沿用现有类型（`Dict`/`Word`/`Article`/`Statistics`/`SettingState` 等），建立 SQLite 表（或「主表存 JSON + 索引列」的混合结构，便于快速起步）。
3. **读写接口**：在 `server/api/` 提供最小读写集（见 03 文档），前端 `stores` 的 `init/setState/save` 改为调用后端 API，替换 `idb-keyval` 的 `get/set`（仅核心 dict/setting 数据）。
4. **练习会话缓存**：**本地为主 + 服务器双备份**。`app/core/utils/cache.ts` 本地读写保持不变，新增 `app/core/composables/usePracticeServerBackup.ts` 负责离开/静止时上传与换浏览器恢复。
5. **迁移**：提供一次性从 IndexedDB（或导出 JSON）导入到服务端的通道（`/api/import`）。
6. **一致性**：个人单用户场景，可先做「最后写入覆盖 + updated_at 校验」，沿用现有 `updated_at`/`version` 比较逻辑。
7. **下线 Supabase**：移除 `app/core/utils/supabase.ts` 依赖，`useDataSyncPersistence.ts` 里的 `fetchServerMeta/upsertServerDatas` 等改为直连后端。
