# TypeWords 私人化改造文档

> 本目录是 TypeWords 项目「私人化改造」的**改造文档系统**——不是一次性的开发计划，而是随改造持续推进、持续维护的一套文档。它记录「改什么、为什么改、怎么改、改到哪了」。

## 文档用途

- **整体概括**：先读 `00-改造总览.md`，它是对全部改动需求的一页式总览。
- **分项说明**：`01`~`04` 按主题拆分，每项遵循统一结构，便于定位与追踪。
- **进度追踪**：每份文档末尾的「状态」字段标记该项进度，随开发更新。

## 已定决策快照

| 决策项 | 结论 |
|--------|------|
| 存储引擎 | **SQLite** |
| 练习会话缓存 | 保留浏览器本地（IndexedDB），不迁服务端 |
| API 返回结构 | 标准 REST + JSON（HTTP 状态码 + 直接资源 JSON）+ OpenAPI，面向 Agent 易读 |
| 认证 | 无认证；提供**可选** `API_TOKEN` 轻量防护（默认关闭） |

## 统一文档结构

每个分项文档按以下小节组织：

1. **改动目标** —— 要达成什么、为什么
2. **现状** —— 当前代码/架构是什么样（含关键文件定位）
3. **方案** —— 建议怎么做（含备选方案、取舍）
4. **涉及文件** —— 需要改动的文件清单（相对项目根目录）
5. **状态** —— 进度标记 + 待确认事项

## 状态约定

| 状态 | 含义 |
|------|------|
| 待开始 | 已明确目标与方案，尚未动手 |
| 进行中 | 正在开发 |
| 已完成 | 开发并验证完成 |
| 待确认 | 方案未定，需要先拍板 |

## 维护约定

- 文档语言：中文（代码路径、标识符、命令保持原文）。
- 每次完成一项改动后，更新对应文档的「状态」和「涉及文件」。
- 新增需求先更新 `00-改造总览.md`，再落到对应分项文档。
